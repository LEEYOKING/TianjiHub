## 0. 结论摘要（先看这四条）

1. **技术栈无需变动，也不需要新增数据库。**
   本项目是 React 19 + TS + Vite 的**纯静态站**：Cloudflare Pages（Git 集成构建）、**无 Worker、无 D1、无 Functions、无服务端 API、无 `.env`、无构建期 secrets**。唯一环境变量是 `import.meta.env.BASE_URL`。
   数据是构建产物：GitHub Actions 在盘后用 Python 生成静态 JSON，前端按需 fetch。
   → 任务书 §12「不要仅因为提到了 D1 就新建一套重复数据库」在本项目上的结论是：**保持现状，不加 D1**。

2. **现在缺的不是"能力"，是"信息分层"。**
   任务书 §4 三层所需能力几乎都已存在（事件/间隔/独立簇/收益/回撤/相对基准/时间轴/热力图/关联/自动总结/配置器）。
   真正缺的新模块只有一个：**§5.1「近期轮动观察」**。其余都是"重新分配主次 + 补齐可解释性"。

3. **发现 1 个高严重度正确性缺陷：位置型可视化存在"索引错位"。**
   主页热力图、详情页事件时间轴、详情页净值曲线这三处，都把 `series.events[]` / `series.pctInWindow[]` 当成**与窗口交易日一一对齐**的数组来按下标取用；但这两个数组实际是**按"该板块有数据的交易日"压缩对齐**的（`series.days`）。
   显然只有在覆盖率 = 100% 时才巧合正确。当前 663 个板块中 **26 个（3.9%）覆盖率 < 100%**，最低 1.7%（`BK1755 2026三季报预增`，120 天里只有 2 天有数据）。
   → 这 26 个板块的热力图颜色、时间轴事件计数、净值曲线会整体错位；且与统计摘要/事件明细不自洽，正好命中任务书 §6.3、§6.4、§9.4 三处硬要求。

4. **统计口径的其余大项实现是对的，不需要重写。**
   复合收益 `∏(1+r)−1`、最大回撤基于净值序列、间隔=交易日序号差、独立簇按冷却期分组、缺失日不当 0、AND/OR 只作用于事件规则内部、大涨事件独立于排行榜判定——这些与任务书 §8 一致（详见 §5「已验证正确项」）。
   阶段 2 的工作量因此集中在"错位修正 + 空档命名 + 口径自洽 + 补测试"，而不是重算公式。

## 5. 已发现的问题（按严重度排序）

### P0-1 位置型可视化的「索引错位」（正确性缺陷）★最高优先级

**现象**：`SectorEventSeries` 的三个数组 `days / pctInWindow / events` 是按**该板块有数据的交易日**压缩对齐的（`series.days.length` = 该板块有效日数），而下列三处代码把它们当成**窗口交易日**下标直接使用：

| 位置 | 代码 | 后果 |
|---|---|---|
| 详情页事件时间轴 | `dates.map((d, i) => { const ev = series.events[i]; const p = series.pctInWindow[i]; })`，而 `dates = comp.dates`（窗口日期） | 覆盖率<100% 的板块，色块与日期错位 |
| 详情页净值曲线 | `for (i=0; i<dates.length; i++) { pv = series.pctInWindow[i]; bench = data.bench[comp.indices[i]] }` | 板块序列与基准/x 轴错位；且 x 轴日期来自 `comp.dates` |
| 主页事件热力网格 | `for (c=0; c<cols; c++) { ev = seriesByRow[r].events[c] }`，`cols = comp.dates.length` | 整行色块右移，事件计数与统计表不一致 |

**证据**：当前 663 板块中 26 个覆盖率 <100%（最低 1.7%），受影响面 3.9%。
**为什么没被发现**：637 个板块覆盖率=100%，此时压缩对齐与窗口对齐恰好重合。

**违反的任务书条款**：§6.3（时间轴与明细可互相验证、事件数量必须一致）、§6.4（曲线口径）、§9.4（各模块不得各用一套）。
**修法（阶段 2）**：在 `ruleEngine` 增加**窗口对齐访问器**（长度 = 窗口日的数组，缺失日为 `null`），并让全部位置型可视化只走访问器；同时把"净值序列 + 回撤"提到 `analytics` 成为单一实现，供详情页曲线与最大回撤共用。

### P0-2 详情页净值曲线与统计摘要口径不一致

- 摘要的 `cumReturn` / `maxDrawdown`：**跳过**缺失日（`valid` 数组）。
- 详情页曲线的板块净值：`p == null ? 1 : 1 + p/100`，即**缺失日当 0 收益**继续累乘。

按 §6.1 顺序（现状顺序已基本吻合，主要缺"数据状态"与"精简"）：

### 第三层：高级研究（抽屉 / 折叠面板）

- 配置器**高级模式**：事件组合规则、独立事件冷却期、关注间隔上下限、波动率相关阈值、活跃度权重（只读展示）。

所有模块必须共享同一份 `WindowComputation + SectorStats[]`；主页各模块的**筛选维度**统一为"规则 scope × 页面筛选"的笛卡尔口径：要么全部忽略页面筛选，要么全部应用——**不允许混用**（P0-3）。
