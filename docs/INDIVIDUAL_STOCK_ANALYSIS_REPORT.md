## 1. 需求背景

### 1.1 现状

**天机枢 v2.0.7+ 当前能力**:
- 大盘总览(指数 + 全市场家数 + 涨跌停)
- 板块涨跌(申万 90 行业 + 同花顺概念)
- 龙虎榜 + 涨停封成比
- 涨停/跌停梯队
- 异动监控(放量突破 / 突破前高 / 低位放量)
- 情绪温度计(5 维,盘中 10 min 实时)
- 涨跌停封成比动态评分(Surgery)

**缺失**:
- ❌ 个股详情页(只有板块/龙虎榜/封板卡级别的列表)
- ❌ 个股多维度分析(技术面/资金面/基本面/消息面/情绪面)
- ❌ 短中期趋势 AI 判断(1-30 天)
- ❌ 个股 K 线 + 技术指标可视化
- ❌ 个股资金流向详情
- ❌ 个股公告/新闻/概念
- ❌ 个股财务数据
- ❌ 个股估值分析
- ❌ 个股股东/机构持仓

### 1.2 用户需求

**核心需求**:
> "针对个股的多维度数据分析 + 未来短中期的趋势 AI 判断"

**5 维度数据**(目标):
| 维度 | 内容 | 频率 |
|---|---|---|
| **技术面** | K 线 / MA / MACD / RSI / KDJ / BOLL / 量价 | 实时 tick + 历史 |
| **资金面** | 主力资金 / 北向资金 / 大单 / 主力净流入 | 实时 tick + 历史 |
| **基本面** | 营收 / 净利润 / ROE / 估值 / 行业地位 | 季度更新 |
| **消息面** | 公告 / 新闻 / 研报 / 社交媒体 | 实时 |
| **情绪面** | 龙虎榜 / 股东 / 概念热度 / 关注度 | 每日 + 实时 |

**短中期 AI 判断**:
- **短期(1-5 个交易日)**: 1-5 天价格走势预测

- **deepseek-v3**: ¥1/M tokens(input),超便宜
- **GPT-4o-mini**: $0.15/M tokens(input),质量高
- **Claude 3.5 Sonnet**: $3/M tokens(input),质量最高

**综合方案**:
- 多因子打分(本地,实时)

- 3 个方案组合,准确度 + 成本平衡

### 2.4 性能可行性 ✅ 完全可行

- 触发式分析(用户主动点)不会压垮系统

## 4. AI 预测模型方案

### 4.1 方案 A:LLM API 推理(⭐ 推荐)

**原理**:
1. 收集个股 5 维数据 → 拼成 prompt
2. 调用 LLM API(Claude/GPT-4o/Deepseek)
3. LLM 推理输出:方向判断 + 关键因素 + 风险提示

**优势**:
- ✅ 灵活,能理解多维数据
- ✅ 输出自然语言,可读性强
- ✅ 不需要训练,直接用
- ✅ 准确度比规则引擎高(LLM 见过大量数据)

**劣势**:
- ❌ 成本($0.01-0.05/次)
- ❌ 延迟 5-15s
- ❌ 不能 100% 准(本质是统计预测)

**Prompt 模板**(示例):
```
你是一位资深 A 股分析师。请基于以下数据,给出 [600519 贵州茅台] 的短中期趋势判断。

【技术面】(实时)
- 收盘价:1680.00 元(+1.2%)
- 5 日 MA:1675 / 10 日 MA:1680 / 20 日 MA:1660
- MACD: 金叉,DIF=+2.3
- RSI(14): 58
- 成交量:5 日均量 1.2 倍

【资金面】(今日)
- 主力净流入:+3.2 亿(超大单+1.8/大单+1.4)
- 北向资金:+0.8 亿(持股 0.85%)
- 大单(>100 万)笔数:15 笔(>5 日均)

【基本面】(2026 Q1)
- ROE:8.5%(同比+0.3%)
- 营收同比增长:+12.3%
- 净利润同比:+15.6%

【情绪面】

- 概念:白酒概念 +2.1%
- 新闻:近 3 日 5 条(2 条利好)

【行业环境】
- 申万二级:白酒 +1.5%
- 北向资金(白酒板块):+5.2 亿

- 上证指数:+0.5%
- 全市场涨跌家数:2400 涨 / 2969 跌
- 涨停/跌停:57/12

请给出:
1. 短期(1-5 个交易日)方向判断:看多/看空/震荡
2. 中期(5-30 个交易日)方向判断:看多/看空/震荡
3. 关键支撑位/压力位

注意:
- 客观中立,不要绝对化("一定涨/一定跌")
```

### 4.2 方案 B:传统机器学习

**原理**:
1. 收集 5 年历史数据(5000+ 只 × 5 维 = 25 万条样本)
2. 提取特征(技术指标 + 资金流 + 财务 + 行业)
3. 训练 XGBoost / LightGBM 二分类模型(涨/跌)
4. 推理时输入当前特征 → 输出涨/跌概率

**优势**:
- ✅ 推理快(< 100ms)
- ✅ 成本低(本地推理,免费)
- ✅ 可解释(feature importance)

**劣势**:
- ❌ 需要大量历史数据(2-5 GB)
- ❌ 需要训练,调参复杂
- ❌ 准确度一般(60-65% 涨/跌)
- ❌ 模型需要定期重训(数据漂移)

**适用**:作为 LLM 的辅助,给出量化分数

### 4.3 方案 C:多因子打分

**原理**:
1. 定义 20-30 个因子(技术/资金/情绪/估值)
2. 每个因子独立打分(-2 ~ +2)
3. 加权求和 → 综合分数
4. 分数 > 0.5 → 看多,< -0.5 → 看空

**因子示例**:
```python
factors = {
    # 技术面 8 个
    "MA5_上穿_MA20": +1.5,
    "MACD_金叉": +1.2,
    "RSI_超买(>70)": -1.0,
    "KDJ_金叉": +1.0,
    "BOLL_突破上轨": +1.5,
    "量比>2.0": +1.2,
    "5日均量>20日均量": +0.8,
    "换手率>5%": -0.5,
    
    # 资金面 6 个
    "主力净流入>1亿": +1.5,
    "主力连续3日净流入": +1.8,
    "北向资金+": +1.0,
    "大单占比>30%": +1.2,
    "超大单持续+": +1.5,
    "融资余额增加": +0.8,
    
    # 基本面 8 个
    "ROE>15%": +1.5,
    "营收同比>20%": +1.5,
    "净利润同比>30%": +2.0,
    "PE<行业均值": +1.0,
    "PB<3": +0.8,
    "毛利率>30%": +1.0,
    "负债率<40%": +0.8,
    "PEG<1": +1.2,
    
    # 情绪面 5 个
    "龙虎榜净买入": +1.5,
    "机构调研>3次/月": +1.0,
    "股东数下降": +1.2,
    "概念热度Top10": +0.8,
    "新闻利好": +0.5,
}

# 加权求和
score = sum(factor_value * weight for factor, value in factors.items())
```

**优势**:
- ✅ 完全可控(每个因子可解释)
- ✅ 实时计算(< 50ms)
- ✅ 免费(本地)

**劣势**:
- ❌ 因子权重需要调
- ❌ 不同股票/不同行情,因子有效性不同
- ❌ 准确度比 LLM 低

**适用**:作为 LLM 的前置筛选 + 实时信号

### 4.4 方案 D:经典技术指标(实时信号)

**MA / MACD / RSI / KDJ / BOLL**:
- 完全本地计算
- 实时信号(均线交叉,超买超卖)
- 0 成本

**适用**:技术面 tab 的实时显示 + 短线信号

| **1 天方向** | 规则引擎(技术面) + LLM 推理 | 55-60% |
| **3 天方向** | 多因子打分 + LLM 推理 | 50-55% |
| **5 天方向** | LLM 推理(综合 5 维) | 50-55% |
| **1 个月方向** | LLM 推理(基本面 + 行业) | 45-50% |
| **3 个月方向** | LLM 推理(长期价值) | 50-55% |

### 5.3 推荐 API

**首选:Deepseek V3**
- 价格:**¥1/M tokens**(input) → 1 user 1 月 < 1 元
- 质量:接近 GPT-4o(中文尤其好)
- 速度:5-10s 返回
- 限制:无明显限制,免费用 API

**备选:OpenAI GPT-4o-mini**
- 价格:$0.15/M(input) → 1 user 1 月 < 0.5 美元
- 质量:高
- 速度:3-5s

**不推荐:Claude 3.5 Sonnet**($3/M input 太贵)

## 12. 合规与风险

### 12.1 法律合规

**A 股信息服务的相关法规**:

| 法规 | 风险等级 | 应对 |
|---|---|---|
| 《证券法》第 138 条(投资咨询业务) | 🔴 高 | **绝对不写"投资建议"** |
| 《金融信息服务管理办法》 | 🟡 中 | 改描述"数据展示" |
| 《广告法》 | 🟢 低 | 正常广告 |
| 《数据安全法》 | 🟡 中 | 数据来源标注 |
| 《个人信息保护法》 | 🟢 低 | 不收集用户信息 |

**核心合规原则**:
- ❌ **不写**: "投资建议" / "目标价" / "买入信号" / "止损点"
- ✅ **改写**: "数据展示" / "技术面分析" / "多维度数据汇总" / "AI 辅助参考"
- ✅ **必须**: 明确 disclaimer "本预测仅供参考,不构成投资建议"
- ✅ **必须**: 数据来源标注(东方财富 / 同花顺 / akshare 等)
- ✅ **必须**: 风险提示(投资有风险,入市需谨慎)

### 12.2 内容红线

**绝对不能出现**:
- "明日会涨" / "明日必跌"
- "X 元是底部" / "目标价 X 元"
- "立即买入" / "立刻卖出" / "止损 X 元"
- "主力正在建仓" / "庄家意图明显"
- "内部消息" / "机构预测"

**可以写**:
- "技术面显示金叉" (客观描述)
- "5 日均线向上" (客观描述)
- "主力资金净流入 +1.2 亿" (客观数据)
- "AI 综合分析偏向看多" (AI 判断,加 disclaimer)
- "风险点:8/15 MLF 到期" (客观提醒)

### 12.3 备案风险

- **个人备案**:可以做"数据展示" / "财经资讯" 类网站
- **企业备案**:如果要商业化(广告/收费),需要金融信息服务资质(60-90 天)
- **风险**:金融办随时抽查,内容违规 → 罚款 + 关站

### 12.4 技术风险

| 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|
| akshare 接口变更/限流 | 中 | 高 | 多数据源(em + sina + 腾讯) + cache |
| LLM API 限额/涨价 | 低 | 中 | 多个 API 备选 + 本地 LLM |
| Cloudflare Workers 限额 | 低 | 中 | Pro 升级 ($5/月) |
| LLM 预测错误 | 高 | 中 | 明确 disclaimer + 不收费 |
| 用户信任危机 | 中 | 高 | 持续回测 + 公开准确度 |

### 12.5 AI 预测失败的应对

**场景**:AI 预测"看多"但实际跌了

**应对**:
1. UI 明确显示置信度(55-70%),让用户知道这是不确定的
2. 列出关键因素,让用户理解判断依据
3. 列出风险点,提醒用户注意
4. 持续回测,公开准确度
5. 用户反馈机制(标记哪些预测不准)

## 附录 B:技术指标计算公式

```python
# MA(N) - N 日简单移动平均
def MA(close, n):
    return close.rolling(n).mean()

# MACD - 平滑异同移动平均
def MACD(close, fast=12, slow=26, signal=9):
    ema_fast = close.ewm(span=fast).mean()
    ema_slow = close.ewm(span=slow).mean()
    DIF = ema_fast - ema_slow
    DEA = DIF.ewm(span=signal).mean()
    BAR = (DIF - DEA) * 2
    return DIF, DEA, BAR

# RSI - 相对强弱指标
def RSI(close, n=14):
    delta = close.diff()
    gain = (delta.where(delta > 0, 0)).rolling(n).mean()
    loss = (-delta.where(delta < 0, 0)).rolling(n).mean()
    RS = gain / loss
    return 100 - (100 / (1 + RS))

# KDJ - 随机指标
def KDJ(high, low, close, n=9, m1=3, m2=3):
    low_n = low.rolling(n).min()
    high_n = high.rolling(n).max()
    RSV = (close - low_n) / (high_n - low_n) * 100
    K = RSV.ewm(alpha=1/m1).mean()
    D = K.ewm(alpha=1/m2).mean()
    J = 3 * K - 2 * D
    return K, D, J

# BOLL - 布林带
def BOLL(close, n=20, k=2):
    mid = close.rolling(n).mean()
    std = close.rolling(n).std()
    upper = mid + k * std
    lower = mid - k * std
    return upper, mid, lower
```
