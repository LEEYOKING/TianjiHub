## 3. 公式与口径变化（交付 3：公式与口径变化）

### 3.1 新增：五段式行为总结（确定性文本，非 AI）

`summarizeBehavior(stats, rule, { benchAvailable, benchmark })`：输入已有统计字段，输出 5 段文本。**不引入任何新的统计量**，只是把字段按 §6.5 的五段重新组织，并补上"统计局限"与"后续观察"。

- A 历史行为：`强势/弱势/大涨/大跌` 次数 + `强势/弱势频率`（分母 = 该板块有效交易日数）。
- B 活跃模式：独立周期数（含冷却期口径）、当前/最长连续、距最近强势步长、间隔均值/中位或"样本不足"。
- C 收益与风险：复合收益、相对基准超额（**简单超额**口径，并显式标注）、最大回撤、波动率、上涨日占比。
- D 统计局限：有效样本/覆盖率、间隔样本数（<4 时明确"不计算集中度、也不宜据此判断规律"）、基准可用性、样本稳定性提示。
- E 后续观察：**可继续验证的条件**（下次是否再次满足强势事件规则、间隔是否落在关注区间、相对超额是否仍为正），末句明确"不是对未来的判断"。

**旧口径 → 新口径**：旧 `describeSector` 输出 4~6 行平铺文本（无"统计局限"，且用"第 X 天"反推事件日）；新版本改为五段结构化输出。**影响范围**：仅详情页文本展示，所有数值仍取自同一份 `SectorStats`，页面其它指标 0 变动。

### 3.2 新增：单板块同步活跃伙伴（口径与主页完全一致）

```
coDays      = #(两个板块在同一交易日都发生强势事件)
jaccard     = coDays / (targetDays + peerDays − coDays)
expected    = targetDays × peerDays / 窗口交易日数
lift        = expected > 0 ? coDays / expected : 0
```
与主页 `computeSyncPairs` 的 Jaccard / Lift 公式、强势事件定义、缺失日处理**完全相同**；差别只在"统计范围限定为与目标板块配对的板块对"。**已用单测逐条比对两者结果，证明口径没有分叉**。

### 3.3 新增：当日真实排名（修正"排名不可追溯"）

时间轴点击面板原用 `view.rankUpAt`（仅在**进入 TOP N** 时才有值），未进榜时显示"—"。现改为直接在当日完整榜单 `comp.ranking[c].ranked` 中定位本板块，得到**真实名次**；跌幅榜名次 = `total − rank + 1`。这样每个事件都能追溯到"涨跌幅 + 排名"（§6.3）。

### 3.4 未变动（明确声明）

事件判定、`gap_i`/`empty_i`、独立簇、复合收益、最大回撤、相对基准**两种口径的既有实现**、`toWindowView` 索引对齐 —— 全部沿用阶段 2/3，本阶段 0 改动。

## 6. 已知问题（交付 6：已知问题）

1. **详情页会全量 `analyzeAll`**：为计算"该板块的同步/领先关系"，详情页需要全部板块的统计（口径与主页一致）。实测无感知卡顿，但比旧版（只算本板块）多一次全量计算；阶段 6 可纳入首屏耗时预算一起测。
2. **`computeLeadLag` 仍为 O(板块数 × 窗口 × 滞后)**：详情页只调用一次（以本板块为 leader），实测可接受；若未来需要"谁是本板块的领先者"（反向查询），需要另写索引，成本更高。
3. **同步伙伴门槛固定为「共同活跃天数 ≥ 2」**：与主页默认 3 不同（详情页要照顾低活跃板块）。两处门槛不同属**有意设计**，但界面上未并列呈现，可能被误读为口径不一致；阶段 5 可考虑统一到配置器。
4. **当日排名取"当日全部有效板块"内的名次**：与「板块范围」（rule.scope）以外的板块不参与排名（排名只在 scope 内进行），这一点在页脚「计算口径」已说明，但仍可能让用户与其它平台的名次不一致。
5. **相对净值曲线的缺失日沿用前值**：与板块/基准线一致（不当作 0 收益），但对覆盖率为 41% 的板块，早期若干天的比值会退化为 "1/1" 附近的平坦段；已在口径卡说明"缺失日沿用前值"。
6. **时间轴一致性自检是"展示型"而非"阻断型"**：不一致时只给 ⚠ 文案，不会阻止渲染（当前数据 100% 一致）。
7. **`browser_evaluate` 在本环境不稳定**：多次返回 `undefined`（疑似只接受单行脚本或上下文限制），导致第 10 项（当日真实排名的具体数值）未能用浏览器实测；该改动逻辑极简（在当日 `ranked` 数组里定位本板块），已由代码审查确认，但**建议你在真机点一次时间轴格子目视确认**。
8. **未做**：§6.6 的"事件明细分页"（当前是"最近 12 条 ↔ 全部"二档）、§9.2 完整数据状态机、§9.3 算法版本号。
